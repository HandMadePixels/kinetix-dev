# MSI Installer Build Guide

## Overview
This guide explains how to package the Kinetix Django application as a standalone Windows MSI installer using PyInstaller and WiX Toolset.

## Prerequisites

### Software Requirements
1. **Python 3.11+** (64-bit)
2. **WiX Toolset 3.11+** - Download from https://wixtoolset.org/
3. **Visual C++ Redistributable** - For PyInstaller
4. **Redis for Windows** - Download from https://github.com/microsoftarchive/redis/releases

### Python Dependencies
All dependencies are in `requirements.txt`. Install with:
```powershell
pip install -r requirements.txt
```

## Build Process Overview

The MSI build process consists of 4 main steps:

1. **Freeze Application** - PyInstaller bundles Python + dependencies
2. **Collect Static Files** - Django static files
3. **Create Installer** - WiX compiles MSI
4. **Sign Installer** - Code signing (optional)

## Step 1: Prepare Application

### 1.1 Update Version
Edit `command_center/__init__.py`:
```python
__version__ = '1.0.0'
```

### 1.2 Collect Static Files
```powershell
python manage.py collectstatic --noinput
```

### 1.3 Create Migrations
```powershell
python manage.py makemigrations
```

### 1.4 Test Application
```powershell
python manage.py test
```

## Step 2: Freeze with PyInstaller

### 2.1 PyInstaller Spec File
The spec file (`installer/command_center.spec`) defines how to bundle the application.

Key sections:
- **datas**: Include templates, static files, migrations
- **hiddenimports**: Django apps and dependencies
- **excludes**: Unnecessary modules (reduce size)
- **runtime_hooks**: Django setup

### 2.2 Run PyInstaller
```powershell
cd installer
pyinstaller command_center.spec
```

This creates:
- `build/` - Temporary build files
- `dist/Kinetix/` - Frozen application

### 2.3 Test Frozen Application
```powershell
cd dist\Kinetix
.\command_center.exe migrate
.\command_center.exe createsuperuser
.\command_center.exe runserver
```

## Step 3: Create MSI with WiX

### 3.1 WiX Source File
The WiX source file (`installer/product.wxs`) defines:
- Installation directory
- Files to install
- Registry entries
- Shortcuts
- Windows service
- Firewall rules

### 3.2 Compile WiX
```powershell
cd installer

# Compile .wxs to .wixobj
candle.exe product.wxs -ext WixUtilExtension

# Link .wixobj to .msi
light.exe product.wixobj -ext WixUtilExtension -out Kinetix-Setup.msi
```

### 3.3 Test MSI
```powershell
# Install
msiexec /i Kinetix-Setup.msi /l*v install.log

# Uninstall
msiexec /x Kinetix-Setup.msi /l*v uninstall.log
```

## Step 4: Automated Build Script

Use the provided build script for automated builds:

```powershell
python installer/build_msi.py
```

This script:
1. Cleans previous builds
2. Collects static files
3. Runs PyInstaller
4. Compiles WiX
5. Creates MSI in `dist/`

## Configuration

### config.ini
The installer creates `config.ini` in the installation directory:

```ini
[server]
host = 0.0.0.0
port = 8000
debug = false

[database]
engine = sqlite3
name = db.sqlite3

[security]
secret_key = <auto-generated>
encryption_key = <auto-generated>

[redis]
url = redis://localhost:6379/0

[api]
virustotal_api_key = 
```

Users can edit this file to configure the application.

## Windows Service

### Service Installation
The MSI automatically installs Kinetix as a Windows service:

- **Service Name**: Kinetix
- **Display Name**: Kinetix Endpoint Management
- **Startup Type**: Automatic
- **Account**: Local System

### Service Management
```powershell
# Start service
net start Kinetix

# Stop service
net stop Kinetix

# Restart service
net stop Kinetix && net start Kinetix

# Check status
sc query Kinetix
```

### Service Logs
Logs are written to:
- `C:\Program Files\Kinetix\logs\command_center.log`
- `C:\Program Files\Kinetix\logs\security.log`
- `C:\Program Files\Kinetix\logs\audit.log`

## Firewall Configuration

The installer automatically creates firewall rules:

```powershell
# Allow inbound HTTPS (port 8000)
netsh advfirewall firewall add rule name="Kinetix HTTPS" dir=in action=allow protocol=TCP localport=8000
```

## SSL Certificate

### Self-Signed Certificate
The installer generates a self-signed certificate:

```powershell
# Certificate location
C:\Program Files\Kinetix\ssl\server.crt
C:\Program Files\Kinetix\ssl\server.key
```

### Custom Certificate
Replace with your own certificate:
1. Copy certificate files to `C:\Program Files\Kinetix\ssl\`
2. Update `config.ini`:
   ```ini
   [ssl]
   cert_file = ssl/server.crt
   key_file = ssl/server.key
   ```
3. Restart service

## Database

### SQLite (Default)
- Location: `C:\Program Files\Kinetix\db.sqlite3`
- Backup: Automatic daily backups to `backups/`

### PostgreSQL Migration
1. Install PostgreSQL
2. Create database:
   ```sql
   CREATE DATABASE Kinetix;
   CREATE USER ccadmin WITH PASSWORD 'password';
   GRANT ALL PRIVILEGES ON DATABASE Kinetix TO ccadmin;
   ```
3. Update `config.ini`:
   ```ini
   [database]
   engine = postgresql
   name = Kinetix
   user = ccadmin
   password = password
   host = localhost
   port = 5432
   ```
4. Migrate data:
   ```powershell
   cd "C:\Program Files\Kinetix"
   command_center.exe migrate
   ```

## Redis

### Installation
The MSI includes Redis installer:
1. Redis is installed to `C:\Program Files\Redis\`
2. Redis service is created and started
3. Default port: 6379

### Configuration
Edit `C:\Program Files\Redis\redis.windows.conf` if needed.

## First Run

After installation:

1. **Access Web Interface**
   - URL: `https://localhost:8000`
   - Accept self-signed certificate warning

2. **Create Admin User**
   ```powershell
   cd "C:\Program Files\Kinetix"
   command_center.exe createsuperuser
   ```

3. **Login**
   - Go to `https://localhost:8000/admin/`
   - Enter admin credentials

4. **Configure System**
   - Go to System Configuration
   - Set server URL, API keys, etc.

## Troubleshooting

### Service Won't Start
1. Check logs: `C:\Program Files\Kinetix\logs\`
2. Verify Redis is running: `sc query Redis`
3. Check firewall rules
4. Verify database exists

### Can't Access Web Interface
1. Check service status: `sc query Kinetix`
2. Verify port 8000 is not in use: `netstat -ano | findstr :8000`
3. Check firewall rules
4. Review `logs/command_center.log`

### Database Errors
1. Check database file exists: `db.sqlite3`
2. Run migrations: `command_center.exe migrate`
3. Check file permissions

### Redis Connection Errors
1. Verify Redis service: `sc query Redis`
2. Test connection: `redis-cli ping`
3. Check `config.ini` Redis URL

## Upgrading

### In-Place Upgrade
1. Backup database: `copy db.sqlite3 db.sqlite3.backup`
2. Run new MSI installer
3. Installer will:
   - Stop service
   - Replace files
   - Run migrations
   - Restart service

### Manual Upgrade
1. Stop service: `net stop Kinetix`
2. Backup database
3. Replace files in `C:\Program Files\Kinetix\`
4. Run migrations: `command_center.exe migrate`
5. Start service: `net start Kinetix`

## Uninstallation

### Via Control Panel
1. Open "Programs and Features"
2. Select "Kinetix"
3. Click "Uninstall"

### Via Command Line
```powershell
msiexec /x Kinetix-Setup.msi /qn
```

### What Gets Removed
- Application files
- Windows service
- Firewall rules
- Start menu shortcuts

### What Stays
- Database (db.sqlite3)
- Configuration (config.ini)
- Logs
- Uploaded files (media/)

## Advanced Topics

### Silent Installation
```powershell
msiexec /i Kinetix-Setup.msi /qn INSTALLDIR="C:\Kinetix"
```

### Custom Installation Directory
```powershell
msiexec /i Kinetix-Setup.msi INSTALLDIR="D:\MyApps\Kinetix"
```

### Network Installation
1. Share MSI on network
2. Deploy via Group Policy
3. Use SCCM/PDQ Deploy

### Code Signing
```powershell
# Sign MSI with certificate
signtool sign /f certificate.pfx /p password /t http://timestamp.digicert.com Kinetix-Setup.msi
```

## Build Optimization

### Reduce MSI Size
1. Exclude unnecessary packages in spec file
2. Use UPX compression (optional)
3. Remove debug symbols
4. Exclude test files

### Faster Builds
1. Use `--noconfirm` with PyInstaller
2. Skip static file collection if unchanged
3. Incremental builds (don't clean every time)
